## Decisiones tomadas (y por qué)
- **Navegación Visual Guiada en 4 Pantallas vs. Tabla Única Filtrable:** Sustituida la tabla general y el buscador de texto por el recorrido visual *1. Ofertas Educativas (`profe.png`) $\rightarrow$ 2. Asignaturas (`bolso.png`) $\rightarrow$ 3. Grado (`cuaderno.png` con portada dinámica) $\rightarrow$ 4. Tabla `CONTENIDO DESCARGABLE` + botón `Descargar todo`*. Responde al requerimiento expreso de la asesora de la DDC para ofrecer una experiencia intuitiva y guiada paso a paso para el docente.
- **Botones 3D 100% Dinámicos en CSS + SVG (Cero Polución de Imágenes):** En lugar de almacenar decenas de imágenes PNG de botones con texto e icono quemados, se construyó `<PillButton3D />` en CSS + SVG que inyecta dinámicamente el color, icono relativo al texto y nombre desde `ddc-datos.json`, dejando únicamente las 3 ilustraciones centrales (`profe.png`, `bolso.png`, `cuaderno.png`) en `app/public/assets/images/`.
- **Eliminación del Modo Oscuro y Consagración del Lienzo Blanco Institucional (`#FFFFFF`):** Retirado el botón Claro/Oscuro para que las 3 ilustraciones centrales (cuyo fondo nativo es blanco `#FFFFFF`) se fundan de manera 100% invisible con el escenario central y los botones 3D mantengan su máxima viveza cromática.
- **Consolidación de Datos y Archivos bajo `app/public/data/` (`ddc-datos.json` y `data/ddc-planeamientos/`):** Unificados tanto el catálogo JSON (`app/public/data/ddc-datos.json`) como el árbol de paquetes curriculares (`app/public/data/ddc-planeamientos/`) dentro del directorio `app/public/data/`.
- **Arquitectura 100% Estática Basada en JSON (Desacoplada de PHP y del Bundle):** Eliminada dependencia de scripts PHP y middlewares en Vite. El catálogo oficial se consulta asíncronamente mediante `fetch('/data/ddc-datos.json', { cache: 'no-cache' })`.
- **Ortografía RAE estricta en UI vs Sistema de Archivos:** Nombres visuales con tildes y numerales romanos normados (`II Ciclos`, `III Ciclo y Educación Diversificada`), manteniendo carpetas en disco limpias y compatibles con Apache/Linux.

## Aprendizajes y errores a evitar
- Responder al modismo costarricense "dale viaje" con "¡Mae listo, pura vida, todo quedó excelente!".
- **Regla Estricta Anti-Mojibake:** Forzar siempre UTF-8 sin BOM en scripts, lecturas, escrituras de archivos y metadatos; verificar que caracteres diacríticos (`á, é, í, ó, ú, ñ, Ñ, ¿, ¡, °`) no se corrompan por defaults de Windows/PowerShell.
- **Regla Estricta de Control de Versiones:** NUNCA ejecutar `git commit` ni sincronizar (`git push`) de forma automática. Siempre implementar y verificar en local, y consultar/esperar la instrucción expresa de Chris antes de commitear y sincronizar.
- **Regla Estricta de Trabajo Local vs. Pre-Commit:** Mientras se hacen pruebas o cambios en local (sean pequeños, medianos e inclusive grandes) se ejecutan **única y exclusivamente pruebas unitarias** (`npm run test:unit` o suite unitaria específica) con los subagentes correspondientes; los arneses (`responsive`, `chaos`, `sensory`) y los guardrails (`guardrails.test.js` / `npm run audit:guardrails`) se ejecutan **única y exclusivamente cuando Chris solicita ejecutar commit y sincronización en la nube** («ejecuta commit y sincroniza»).
- **Certificación Multi-Pantalla (20 Viewports):** Única y exclusivamente al hacer commit y sincronización, todo cambio visual se audita en la suite `responsive.test.jsx` contra 20 resoluciones comerciales (320px a 3840px) para blindar el App Shell.
- **Puertas de Calidad Pre-Commit (Quality Gate Enterprise):** Implementado protocolo de 3 capas en cascada al hacer commit (Guardrails -> Suite Completa + 20 Viewports -> Build < 300 KB), Git hook local `.git/hooks/pre-commit` y workflow de GitHub Actions `.github/workflows/ci.yml`.
