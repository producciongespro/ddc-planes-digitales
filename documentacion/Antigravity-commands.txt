

Comandos:


1. Comandos de la Interfaz (Slash Commands)

Estos comandos los puedes escribir directamente en el chat para automatizar flujos:

/plan: Solicita un análisis y desglose paso a paso antes de escribir código. Muy recomendado para diseñar arquitecturas de agentes o tareas grandes.
/grill-me: Inicia una sesión interactiva donde te haré preguntas técnicas clave para afinar requisitos y resolver decisiones de diseño antes de implementar.
/goal: Activa un modo autónomo y exhaustivo para tareas largas, donde el agente no se detiene hasta verificar que el objetivo esté 100% cumplido.
/learn: Permite al agente aprender y persistir reglas, correcciones o configuraciones del proyecto para sesiones futuras.
/schedule: Programa tareas recurrentes o temporizadores de seguimiento.
/browser: Útil cuando una tarea requiere navegar e interactuar con aplicaciones web o documentación externa.



2. Capacidades de Agentes y Subagentes

Para cuando configuremos y deleguemos tareas a subagentes en este entorno, disponemos de las siguientes operaciones:

Subagentes Nativos Predefinidos:

self: Invoca una copia del agente principal con todas sus herramientas (para paralelizar trabajo o trabajar en ramas aisladas).
research: Subagente optimizado para lectura y análisis del repositorio o documentación sin modificar archivos ni saturar el contexto principal.

Creación Dinámica de Subagentes (define_subagent):

Podemos crear subagentes a medida asignándoles un system_prompt específico, su rol y su set de permisos (por ejemplo: si tienen acceso a ejecutar comandos en la terminal, editar código o consultar MCP).

Orquestación y Ciclo de Vida:

Invocación (invoke_subagent): Ejecuta uno o múltiples subagentes en paralelo, pudiendo elegir workspace compartido (inherit/share) o aislado (branch).
Comunicación (send_message): Permite enviarle instrucciones adicionales o contexto a un subagente en ejecución.
Control (manage_subagents): Permite listar subagentes activos (list), monitorear su estado o cancelarlos (kill/kill_all).



3. Personalización Avanzada (Skills, Reglas y MCP)

Más adelante podemos configurar:

Custom Skills (SKILL.md): Instrucciones reutilizables, scripts y recursos empaquetados para tareas complejas.
Rules / Reglas: Instrucciones persistentes a nivel de repositorio o globales para forzar convenciones de código (PSR, Git flow, etc.).
MCP (Model Context Protocol): Conexión con servicios externos, bases de datos o APIs.
